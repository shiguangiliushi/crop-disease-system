**核心设计取舍**

| 决策 | 选择 | 理由 |
|---|---|---|
| 语料规模 38 词条 + 190 措施 | **先不做向量库**，关键词 + `pest_lookup` 复用 | 上 faiss/chroma 只会增加依赖和不确定性，收益接近零 |
| 生成失败怎么办 | **降级返回词条原文**，标注"AI 暂不可用" | 识别页是主链路，助手是增强功能，不能反向拖垮 |
| 会不会瞎答农药 | **无来源不回答**（`sources` 为空时只回固定话术） | 农业场景答错药是事故，不是体验问题 |
| 会话存哪 | 新建 3 表，**不复用** `Conversation`（那是私信） | 私信与会话语义完全不同，混表会让两边查询都变脏 |

## 三、数据模型（`models_assistant.py`）

```python
class AssistantSession(models.Model):
    """一次连续对话。一个用户可有多个会话。"""
    user        = FK(CustomUser, on_delete=CASCADE, related_name='assistant_sessions')
    title       = CharField(max_length=80, blank=True, default='')   # 取首问前 30 字
    pest        = FK('PestInfo', null=True, blank=True, on_delete=SET_NULL)  # 从识别页进来时绑定
    detection   = FK('DetectionHistory', null=True, blank=True, on_delete=SET_NULL)
    created_at  = DateTimeField(auto_now_add=True)
    updated_at  = DateTimeField(auto_now=True)
    # 索引：user + -updated_at（会话列表的唯一查询形态）

class AssistantMessage(models.Model):
    """一条消息。role 决定谁说的。"""
    ROLE = (('user', '用户'), ('assistant', '助手'), ('system', '系统'))
    session     = FK(AssistantSession, on_delete=CASCADE, related_name='messages')
    role        = CharField(max_length=10, choices=ROLE)
    content     = TextField()
    # 生成侧元数据（用户消息全为空）
    model       = CharField(max_length=40, blank=True, default='')
    degraded    = BooleanField(default=False)   # True = 走了降级（词条原文/无 AI）
    latency_ms  = PositiveIntegerField(default=0)
    prompt_tokens     = PositiveIntegerField(default=0)
    completion_tokens = PositiveIntegerField(default=0)
    created_at  = DateTimeField(auto_now_add=True)
    # 索引：session + id（按时间正序取消息）

class AssistantCitation(models.Model):
    """答案引用了哪条知识。**必须能溯源**，前端点得开。"""
    message     = FK(AssistantMessage, on_delete=CASCADE, related_name='citations')
    pest        = FK('PestInfo', null=True, blank=True, on_delete=CASCADE)
    prevention  = FK('PreventionMethod', null=True, blank=True, on_delete=CASCADE)
    snippet     = CharField(max_length=200)   # 引用原文片段，前端高亮用
    score       = FloatField(default=0)       # 检索得分，便于事后调参
```

**为什么要 `degraded` 和 token 字段**：这是事后唯一能回答"用户看到的差答案，是模型笨还是我们没给知识"的证据。没有它，效果问题只能靠猜。

**与既有表的关系**

- 只**读** `PestInfo` / `PreventionMethod`；不新增知识字段（要补语料就补这两张表，别开新表）。
- 转人工时**写**既有的 `ConsultQuestion`（`models_expert.py`），并给 `AssistantMessage` 记一条"已转人工"，让 `ConsultAnswer` 的链路自然接上。

**提示词约束（`prompts.py` 的硬性要求）**

1. 只允许使用 `<knowledge>` 块内的信息，块外一律不许补充。
2. 涉及农药：只复述语料出现的成分/浓度/间隔；语料没写就回答"词条未收录，建议咨询当地植保站"。
3. 输出结构固定：结论 → 依据 → 防治建议 → 何时需要人工。
4. 引用要标 `[1]` `[2]`，序号对应 `citations` 顺序，供 `citations.py` 反查校验。

## 五、接口契约

**`POST /api/assistant/ask`**（需登录，`IsAuthenticated`）

```jsonc
// 请求
{ "question": "这个病打什么药？", "session_id": 12, "pest_identifier": "tomato___late_blight" }

// 200 响应
{
  "session_id": 12,
  "message_id": 88,
  "answer": "……",
  "degraded": false,
  "citations": [{ "pest_id": 32, "prevention_id": 442, "snippet": "选用抗病品种……" }],
  "usage": { "prompt_tokens": 1200, "completion_tokens": 260, "latency_ms": 3400 }
}
```

**`POST /api/assistant/ask/stream`**：同请求体，`Content-Type: text/event-stream`，事件序列

```
event: meta      data: {"session_id":12,"message_id":88,"degraded":false}
event: delta     data: {"text":"这个病"}            ← 多条
event: citations data: {"citations":[...]}          ← 生成结束后一次性校验后的引用
event: done      data: {"usage":{...}}
```

**`POST /api/assistant/messages/<id>/feedback`**：`{"verdict":"helpful|useless|escalate","note":""}`；
`escalate` 时服务端写 `ConsultQuestion` 并回 `{"consult_question_id": 7}`。

**错误约定**：参数错 400；未登录 401；超出会话/频率上限 429；LLM 不可用**仍返回 200 且 `degraded=true`**（这是刻意的，便于前端区分"答得保守"与"请求失败"）。

1. **实际落到的模型是 `deepseek-flash`，不是 `deepseek-chat`** —— 请求 `deepseek-chat`

2. **延迟基准**：本次是极短请求（11 prompt tokens）0.8 s。真实回答的输入会是

   否则用户在 5–10 s 内看不到任何反馈。

## 十、明确不做（避免误会）

- **不做**多轮长对话记忆压缩：`ASSISTANT_SESSION_MAX_MESSAGES` 到顶就新开会话，不做摘要。
- **不做**通用聊天机器人：问题与农业无关时直接兜底话术，不陪聊。
- **不做**模型微调：知识与表达都在提示词和语料里，权重不动。
- **不改** `services_translate.py` 与 YOLO 识别链路：助手是旁路，`ai_service.py` 一行不动。
