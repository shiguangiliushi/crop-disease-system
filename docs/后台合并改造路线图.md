# 后台管理功能合并改造（路线图）

> 2026-xx 用户确认"全部做"。分四批推进，**每批都必须保持可运行、跑通检查与测试、写记录、推送到 GitHub**。
> 本文是路线图与不变量清单；每批的实际结果追加在 `docs/系统完善记录.md`。

## 为什么要合并

后台有 12 个侧栏入口，其中三组是"同一件事散在多处"。最典型的一次事故：
**同一个"驳回"动作存在于「审核队列」和「论坛管理」两个页面**，
用户按了其中一处、发现"没用"，排查了一轮才发现是两处口径不同。
合并的目的不是"看着整齐"，而是**让一个动作只有一个入口** —— 从结构上消灭这类混淆。

## 四批计划

| 批次 | 合并 | 现状 | 目标 | 关键约束 |
|---|---|---|---|---|

预期结果：侧栏从 12 项收到 **7 项左右**
`数据看板 ｜ 内容管理 ｜ 用户管理 ｜ 新闻管理 ｜ 病害百科维护 ｜ 意见反馈管理 ｜ 系统`

## 不变量（每批都必须成立）

1. **五个内容模块的授权语义不变** —— `review` / `forum` / `news` / `pests` / `feedback` 描述的是"这个人干什么活"，
   不是"他点哪个菜单"。合并只改**"模块 → 页面"的映射与界面**，不动授权语义。
2. **不可逆动作仍仅全权管理员** —— 删帖、批量删帖、彻底删评论、批量删反馈（口径见 `api/capabilities.py`）。
3. **不允许出现"按钮在、权限没有"** —— 前端显示的每个入口/页签/按钮，后端都必须放行；
   反之，后端拒绝的动作前端不该显示（第 181/182 批就是修这类缺陷）。
4. **旧地址必须保留跳转** —— 书签、文档、E2E 里的老链接不能失效（项目已有先例）。
5. **权限矩阵表是唯一来源** —— `backend/api/role_matrix.py` 的 `MODULE_PAGES` 与侧栏必须一致，
   由 `api.tests.RoleMatrixTests` 强制（它会解析 `AdminLayout.vue`，"侧栏有的，矩阵必须知道"）。

## 每批的验收清单

```
后端：python manage.py test api.tests.RoleMatrixTests api.tests.RoleMatrixEndpointTests   # 必须绿
     改了权限代码 → 再跑相关测试类
前端：cd frontend
     npm run check        # i18n 中英对称 / 组件注册 / docTitles 等 6 条
     npx vitest run       # 单测
     npm run build-only   # 构建
浏览器：相关 verify-*.mjs（管理端身份注入要补齐 is_superuser/capabilities —— CustomUserSerializer 不含这些字段）
文档：追加 docs/系统完善记录.md 一节；跑 check_line_endings.py 与 check_md_links.py
提交：git add <明确路径> → git commit -F 消息文件（不要用 -m，中文会被 PowerShell 弄坏）
推送：docs/tools/push_and_verify.py；被阻断则每 45 秒重试（最多 40 次），直到远端 == 本地 HEAD
```
