# 游客试用方案（免登录 3 次识别 / 5 次问答）

> 目标：任何人打开 `www.shiguangiliushi.com`，**不注册**就能上传一张叶片图看识别结果、问助手一个问题。
> 场景很具体：把链接发给面试官 / 技术总监，他在 60 秒内点得通，而不是先填一遍注册表单。
>
> 本文是**方案**，不是实现记录。落地后把「第 439 批」写进 `docs/系统完善记录.md`，并回收本文件的「待定」项。
>

## 一、为什么现在点不通（现状盘点）

| 位置 | 现在 | 后果 |
|---|---|---|
| `REST_FRAMEWORK['DEFAULT_PERMISSION_CLASSES']` | `IsAuthenticated` | 除显式 `AllowAny` 的接口外，全部要登录 |
| `DetectView` | `permission_classes = [IsAuthenticated]` | 上传图 → 401 |
| `AssistantAskView` / `AssistantAskStreamView` | 同上 | 提问 → 401 |
| 前端路由 `/detect` `/assistant` `/history` | `meta.requiresAuth: true` | 直接跳登录页 |
| 前端 `utils/http.js` | 401 → 清登录态 + 跳登录页 | 试用时的 401 会把人**踢走**，而不是提示"注册继续" |

已经**不**需要改的部分：预警列表、病害详情、论坛帖子列表、公开主页这些本来就有匿名入口
（`permission_classes = [AllowAny]`，如 `views_alert.py` 第 216 批的说明：把实时数据藏到登录后面，
等于让第一屏全是静态文案）。也就是说游客现在能看到"这个站有什么"，唯独**用不了**它的核心能力。

## 二、三个候选方案与取舍

| | A. 匿名接口直连（不建用户） | B. 单个共享游客账号 | **C. 每人一个临时游客用户（选定）** |
|---|---|---|---|
| 识别历史 | 不能落库（`DetectionHistory.user` 是**必填**外键），只能返回一次结果 | 能落库，但**所有游客共用一个历史页** —— A 面试官会看到 B 的叶片照片 | 能落库，历史天然隔离 |
| 助手问答 | `orchestrator.ask()` 强依赖 `user` + 会写 `AssistantSession/AssistantMessage`，要为此改主链路 | 能用，但多人会话混在一起 | 全部原样可用，**零改动** |
| 代码改动 | 要动识别/问答的核心链路（分叉出第二条路径） | 小 | 中（新增模型 + 闸门 + 清理） |
| 统计污染 | 无（不写库） | 有 | 有，但可用 `is_guest` 一处排除 |
| 数据清理 | 无 | 无 | 需要定时删 |

**选 C 的核心理由**：这个项目最反对的就是"同一个逻辑写两遍"。A 方案会让识别与问答长出第二套入口，
而 C 是把"游客"当成一个**普通用户**，识别、追问、历史、审计、限流全部复用现有代码 ——
新增的只是一个身份来源、一道闸门、一条清理命令。

B 被否掉的原因很实际：总监转发链接给同事，两个人同时点，会看到对方的识别记录和会话。

## 三、方案全貌

```
浏览器首次进入 /detect 或 /assistant
   │  （无 auth_token，且 localStorage 里没有未过期的 guest_token）
   ▼
POST /api/guest/session/            ← 唯一的"开试用"入口，限流兜底
   │  1. 建一个临时用户 guest_<12hex>（set_unusable_password / is_guest=True）
   │  2. DeviceToken.issue(user, device='web')
   │  3. 返回 { token, quota: {detect_left, ask_left, resets_at} }
   ▼
前端把 token 当普通登录态存（沿用 authStorage.js 的键名），多带一个 is_guest 标记
   │
   ├─ POST /api/detect/            → 正常识别 + 写 DetectionHistory（属于这个临时用户）
   ├─ POST /api/assistant/ask/     → 正常问答（会话/消息落在临时用户名下）
   ├─ GET  /api/guest/quota/       → 顶部"试用中·剩余 N 次"
   └─ 其它写接口                    → 403，提示"注册后可用"
   ▼
每天 04:xx  prune_guests 删掉 3 天未活动的临时用户（CASCADE 带走历史/会话）
          紧随其后的 prune_media 收走因此变成孤儿的图片文件
```

## 四、数据模型（迁移 `0079`，当前最新是 `0078_adminauditlog_feedback_delete`）

### 1）`CustomUser` 加一个字段

```python
# api/models.py · CustomUser
is_guest = models.BooleanField('游客试用账号', default=False, db_index=True)
```

为什么用字段而不是"用户名以 guest_ 开头"：**前缀是约定，字段是约束** ——
将来改名规则、或有人真注册了 `guest_abc` 这种用户名，靠字符串判断会静默错。
`db_index=True` 是因为统计页每次都要 `exclude(user__is_guest=True)`。

### 2）日配额表

```python
class GuestTrialQuota(models.Model):
    """游客试用额度：(IP 哈希, 自然日) 一行，两个计数器。

    ⚠️ 为什么落库、不落 cache：见 §六「限额为什么不能靠缓存」。
    """
    ip_hash = models.CharField(max_length=64, verbose_name='IP 的 SHA256 前 16 位')  # 不存明文 IP
    day = models.DateField(verbose_name='自然日（Asia/Shanghai）')
    detects = models.PositiveSmallIntegerField(default=0, verbose_name='当日已识别次数')
    asks = models.PositiveSmallIntegerField(default=0, verbose_name='当日已问答次数')
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        constraints = [models.UniqueConstraint(fields=['ip_hash', 'day'], name='guest_quota_uniq')]
        indexes = [models.Index(fields=['day'], name='guest_quota_day_idx')]
```

**只存哈希，不存明文 IP**：这张表是"防刷计数器"，不是审计表；审计日志（`AdminAuditLog.ip`）已经有明文 IP 的合法用途，不要在这张表里再存一份。

### 3）`DetectionHistory` / `AssistantSession` 不动

两者对 `user` 都是 `CASCADE`，所以删游客用户 = 连带删掉他的识别记录、会话、消息。
这是选 C 的最大红利：**清理不需要写一行删除逻辑**。

## 五、接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/guest/session/` | 匿名 | 开一次试用，返回 token + 剩余额度；已有有效 token 则直接返回同一份 |
| GET | `/api/guest/quota/` | 游客 / 登录用户 | 剩余次数 + 额度重置时间（登录用户返回 `unlimited: true`） |
| POST | `/api/detect/` | 改：游客可用（走额度） | 其余逻辑一行不改 |
| POST | `/api/assistant/ask/`<br>`/api/assistant/ask/stream/` | 改：游客可用（走额度） | **游客不允许带图**（vision 单价高，见 §七） |
| DELETE | `/api/detection-history/clear-all/` | 游客可用 | 让他能自己清掉试用痕迹 |
| 其它写接口 | — | **403** | 发帖/评论/反馈/私信/举报/改资料/注销一律拒绝 |

### 额度怎么扣（原子，别先读后写）

```python
# api/guest.py
def consume(kind: str, *, request) -> tuple[bool, int]:
    """扣一次额度。返回 (是否放行, 剩余次数)。kind ∈ {'detect','ask'}"""
    ip_hash = _ip_hash(request)          # sha256(f'{SECRET_KEY}:{audit._client_ip(request)}')[:16]
    day = timezone.localdate()           # Asia/Shanghai 的自然日
    limit = settings.GUEST_TRIAL[kind]   # detect=3 / ask=5

    obj, _ = GuestTrialQuota.objects.get_or_create(ip_hash=ip_hash, day=day)
    # 一条 UPDATE ... WHERE detects < limit：并发两次请求只有一个能成功。
    # 和 OpsPendingWrite 的"认领"是同一个套路 —— 先查后改在双击/重放面前必错。
    updated = (GuestTrialQuota.objects
               .filter(pk=obj.pk, **{f'{kind}s__lt': limit})
               .update(**{f'{kind}s': F(f'{kind}s') + 1}))
    left = limit - getattr(GuestTrialQuota.objects.get(pk=obj.pk), f'{kind}s')
    return bool(updated), left
```

> ⚠️ 超额时**不要**回 429。429 是"你太快了，等等再来"，而这里的语义是"免费额度用完了" ——
> 回 **402**（或 403 + 业务码 `GUEST_QUOTA_EXCEEDED`），前端才能正确地弹"注册继续"而不是"请稍后再试"。
> 响应体必须带上 `reset_at`，否则用户不知道要等到什么时候。

## 六、两道闸门

### 闸门 1：额度的权威计数在库里，`ScopedRateThrottle` 只当兜底

`settings.py` 的 `DEFAULT_THROTTLE_RATES` 补两条（**少一条就等于没限流**，第 35 批的坑）：

```python
'guest_session': '6/min',    # 开试用：同一 IP 每分钟最多建 6 个临时身份
'guest_detect':  '10/hour',  # 识别：兜住"换个 IP 继续刷"以外的突发
'guest_ask':     '15/hour',
```

**为什么额度不能只靠缓存**（这条必须写进代码注释，否则下一个人会"优化"掉）：
`settings.py` 里已经写明，生产环境若没配 `DJANGO_CACHE_URL` 会**回落到 LocMemCache 并警告** ——
LocMem 是**每进程一份**，gunicorn 起 4 个 worker 就等于把 3 次/天变成 12 次/天，而且**不报错**。
所以日额度必须落库；限流只负责挡"一秒内连点 50 次"这种突发。

### 闸门 2：游客能写什么，由**认证层**决定，不写在 `permission_classes` 里

项目里大量视图显式写了 `permission_classes = [IsAuthenticated]`（识别、问答正是如此），
所以**任何挂在 `DEFAULT_PERMISSION_CLASSES` 上的闸门都会被这些视图绕过去**。闸门要放在更早的层：

```python
# api/authentication.py
class GuestTokenAuthentication(DeviceTokenAuthentication):
    """游客 token 只放行打了 `guest_allowed = True` 的视图，其它一律 403。

    ⚠️ 为什么在认证层、不在 permissions 层：权限类会被视图自己的
       `permission_classes = [...]` 整个覆盖，而认证类不会 —— 见 §六·闸门 2。
    """
    def authenticate(self, request):
        result = super().authenticate(request)
        if not result:
            return result
        user = result[0]
        if getattr(user, 'is_guest', False):
            view = (request.parser_context or {}).get('view')   # DRF 在 initialize_request 里放好
            if not getattr(view, 'guest_allowed', False):
                raise PermissionDenied('试用账号只能使用识别与问答，注册后可用完整功能')
        return result
```

然后**只在 5 个类上写字**：`DetectView`、`AssistantAskView`、`AssistantAskStreamView`、
`DetectionHistoryClearView`、`LogoutView` 各加一行 `guest_allowed = True`。

默认拒绝、逐处放行 —— 与"写工具单独注册表"同一个思路：**安全边界写在漏不掉的地方**，
而不是"我记得别在别处写"。

## 七、几个必须做的限制（每一条都对应一个真实风险）

| 限制 | 为什么 |
|---|---|
| 游客**不能给助手传图**（`image` 参数直接 400） | vision 请求单价高；一个脚本刷 3 次/天 × N 个 IP 就能烧掉额度。纯文本问答已足够展示 Agent 能力 |
| 游客 `username` 不可枚举、不可登录 | `set_unusable_password()`；`authenticate()` 对它必然失败 —— 不能出现"猜中用户名就能进后台" |
| 游客写操作全 403，**包括改密码/邮箱/头像/注销** | 这些接口走的是 `request.user`，不做闸门就能被试用 token 调用 |
| 游客 `role='USER'`、不给任何 capability | 管理端能力判定（`capabilities.py`）本来就与 role 相关，但**不要赌** —— 显式给最小权限 |
| 额度按 IP，不按 token | 否则"清 localStorage 再进一次"就是无限次。身份 TTL 与额度**故意解耦**：换身份不带来新额度 |
| `Retry-After` / `reset_at` 必须回 | 前端要显示"明天 00:00 重置"，否则用户以为坏了 |

## 八、统计口径：游客不能污染管理端

游客的识别记录会进 `DetectionHistory`，而全站约 **9 处**聚合直接吃这张表：

| 文件 | 用途 |
|---|---|
| `views_dashboard.py:220` | 管理端数据看板 |
| `views_system_health.py:55/122` | 系统健康「模型使用」与 14 天趋势 |
| `views_detections_admin.py:147` | 管理端识别记录列表 |
| `services_alert.py:74/89/99/114/122/318` | 病害预警的"近 7 天热度" |
| `views_calendar.py:177/187/209/264/284` | 农事日历的识别分布 |
| `assistant/ops/tools.py` | 助手的 `get_ops_stats` / `get_detection_errors` / `get_feedback_samples` |

做法：给 QuerySet 加一个方法，把这 9 处从 `.all()` 换成 `.real_users()`。

```python
# api/models.py
class DetectionHistoryQuerySet(models.QuerySet):
    def real_users(self):
        """排除游客试用账号。⚠️ 只在**统计与列表**里用；
        游客自己看历史走的是 `filter(user=request.user)`，不要套这个。"""
        return self.exclude(user__is_guest=True)
```

验收方式是一条契约测试，而不是读代码确认：

```python
def test_guest_detection_does_not_move_admin_stats(self):
    before = AdminHealthView._runtime_model_stats()   # 或对应的统计函数
    guest_detect_once()
    self.assertEqual(AdminHealthView._runtime_model_stats(), before)
```

## 九、清理与运维

```bash
# 新增命令：删掉 N 天没活动过的游客账号（CASCADE 带走历史/会话/消息）
python manage.py prune_guests --days 3 --dry-run
python manage.py prune_guests --days 3 --yes
```

- **图片文件不用它删**：`prune_media` 的判据是"没有任何 FileField 引用"，
  用户一删、`DetectionHistory` 行跟着没了，文件自然变成孤儿 —— 跑完 `prune_guests`
  之后那条每天 04:00 的 `prune_media --yes --min-age-days 7` 会收走。
  两条任务**顺序无所谓**，但间隔别超过一天，否则磁盘多留一批图。
- **定时任务从"五件事"变"六件事"**：`docs/部署与运维.md` §定时任务一览 要加一行，
  并在"缺一件都是安静的故障"那张表里注明"游客数据只增不减"这一后果。
- `check_env` / `/api/health/` 建议加一项 `guest_retention`：最长多久没清理过（同备份新鲜度那套）。

| 8 | 清 localStorage 后再进 | 额度不重置（按 IP 计） |
| 9 | 登录用户带 token 走同一条链路 | 完全不受影响（回归：登录用户额度视为无限） |
| 10 | `guest_token` 打管理端 12 个接口 | 全 403（逐个列在参数化测试里，防止将来新增接口漏挡） |

## 十三、不做什么（明确的边界）

1. **不做"免注册即可发言"** —— 论坛是产品核心，一旦开放就是垃圾广告入口，且没有账号可封。
2. **不做邮箱验证码/手机号** —— 试用身份刻意不留任何 PII，连邮箱都不填。
3. **不把游客账号算进"用户数"** —— 管理端用户列表默认过滤 `is_guest=True`（与 §八 同一理由）。
4. **不给游客看管理端任何页面** —— 连"助手质量看板"也不给，那是给管理员看的。
