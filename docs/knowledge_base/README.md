这里是「智能回答助手」要用的语料底座。**入库只读本目录的 JSON，不要读 `初稿_勿入库/`。**

## 数据概览（已校验）

```
版本 1.0 · 校准日期 2026-10-14 · 共 38 条 = 26 病害 + 12 健康作物
每条 7 个维度（26×7 + 12×7 = 266 个维度字段，一个不缺）
病害维度：症状描述 / 发病规律 / 农业防治 / 化学防治 / 生态防治 / 物理防治 / 监测预警
健康维度：健康形态特征 / 健康生长条件 / 农业健康管理 / 化学保护 / 生态健康管理 / 物理保护 / 健康监测
每条附 scientific_name（拉丁学名）、host_crop、sources（来源 URL）、calibration_notes（修订说明）
```

单条信息量：症状描述**均长 214 字**（库内现有摘要 40 字、初稿 PDF 93 字），
化学防治均长 220 字，含登记剂量、稀释倍数、安全间隔期与 FRAC 轮换。

## 怎么用（入库映射）

完整映射与落地步骤见 [../知识库入库方案.md](../知识库入库方案.md)。要点：

- 26 条病害 → 既有 `PestInfo` + `PreventionMethod`，**零 schema 改动**；
  其中「发病规律」对应的是**既有**字段 `PestInfo.description`（不是新字段）；
- 12 条健康记录 → 需新建 `CropHealthProfile`；
- 需新增字段：`PestInfo.scientific_name`、`PestInfo.sources`；
- **幂等**：写入前先删该 `pest` 的旧 `PreventionMethod`（该表无唯一约束，否则重复导入翻倍）；
- 一处名字不一致：JSON 的「番茄**斑靶**病」在库里叫「番茄**靶斑**病」，
  必须按 `english_identifier = tomato_target_spot` 匹配。

## 维护约定

1. **不要就地改 JSON 的字段名或结构** —— 下游入库脚本按固定键名读取；
2. 内容修订请改 JSON 并同步 `metadata.calibration_date`，同时在
   [数据校准说明.md](数据校准说明.md) 记一条修订要点（为什么改、依据哪个来源）；
3. 化学防治有**时效性**（农药登记状态、抗药性水平会变），约定**每 1–2 年复核一次**；
4. 本知识库不构成农药使用推荐 —— 助手回答涉及用药时必须带
   "以当地植保站当期防治方案为准"这句（详见入库方案的提示词约束）。
