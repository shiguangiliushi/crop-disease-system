## 一、结论速览

- 清单**方向基本正确**，但并非全部缺失：**识别报告 PDF 导出、病害分布/月度趋势统计、收藏、
  图表、无密码落地（本轮修复）** 等能力项目里已经有了。
- 有 **2 项属于"文档写了、代码没做"**：
  1. `views_forum.py` 的文档字符串写着"防刷限制和敏感词过滤" —— 敏感词**没有任何实现**；
     限流虽然挂了 `UserRateThrottle`，但因为 `settings.py` 里**没有配置速率**，实际恒为放行。
  2. `LikeViewSet.create` 调用 `self.send_like_notification(...)`，而该方法**从未定义** ——
     这是"被点赞通知"功能的残骸，会让 `POST /api/forums/likes/` 直接 500（本轮已移除死调用）。
- 安全项里**最重要的一条属实且严重**：登录页把**明文密码**写进 `localStorage`（本轮已修）。

## 三、本轮已修的两个真问题（历史记录，均已修复并固化）

### 1. 明文密码落地（严重）

- **问题**：`LoginView.vue` 的 `savePassword()` 把明文密码写进 `localStorage.saved_passwords`
  （形如 `{"admin":"123456"}`），同源脚本可任意读取，共用电脑或 XSS 场景下直接泄露。
- **修复**：
  - 删除 `savePassword/loadPassword/clearSavedPassword` 与该存储键；
  - "记住我"语义改为**只记住登录状态**（token 持久化，由 auth store 负责），文案改为「记住登录状态」；
  - 密码交给**浏览器自带密码管理器**（`autocomplete="current-password"` 已就位）；
  - 进登录页时**主动清除历史遗留的 `saved_passwords`**（老用户升级后第一次打开就清掉）。
- **验证（Edge 实测）**：写入 `{"admin":"123456"}` 后打开登录页 → 键已被清除；
  勾选"记住登录状态"登录后，`localStorage` 只剩 `auth_token / user / all_usernames / last_username / remember_me_*`，
  **没有任何键包含密码**。

### 2. 点赞接口必然 500（隐患）

- **问题**：`LikeViewSet.create` 调用 `self.send_like_notification()`，全项目无此方法 → `AttributeError` → 500。
  前端点赞走的是 `PostViewSet.like`（`/forums/posts/{id}/like/`），所以一直没被暴露，
  但 `POST /api/forums/likes/` 是**注册在路由上的公开接口**。
- **修复**：移除该死调用并注明原因（等真正实现通知功能后再接回来）。
