## 四、不做（9 条，写清理由，避免以后反复讨论）

| 事项 | 不做的理由 |
|---|---|
| 多登录方式（手机号 / OAuth） | 产品定位问题，不是技术缺口；登录不是这个系统的看点 |
| 地块 / 作物档案 | **另一个产品**：需要地块维度的数据模型与录入流程，会把"完整"做成"半成品拼盘" |
| 防治闭环（用药记录 + 复诊提醒） | 同上，且需要真实的施药数据才有意义 |
| 分享海报 / 二维码 | 传播向功能，与识别主链路无关 |
| 换回标准 Vite | 现在 `rolldown-vite` + `treeshake:false` 是**能跑**的状态；为"产物偏大"换回去、再踩一次白屏，不值得 |
| 第三方气象 / 植保数据 | 需要付费或申请接口；页面已如实标注"预警仅基于站内记录" |
| 运维助手 L2 归因 | 之前已定：数据模型就绪，但口径错了就是假结论；没有新需求不做 |
| function calling（v2） | 同上；路由表已就位，纯增量，不急着做 |
| 看板钻取 / 实时刷新 | 管理端单人使用，现有"最近 N 天"够用 |

第四条的产品延展（严重程度分级、多图对比等）**不在本文范围**：那些属于"要不要做下一个产品"的决定，不是缺口。
