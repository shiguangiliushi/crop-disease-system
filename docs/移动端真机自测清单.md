# 移动端真机自测清单

> 第 175 批新增。自动化能覆盖的部分在 `mobile/scripts/`（外壳、页面一致性、主链路），
> 但**真机上的这几类问题自动化测不出来** —— 浏览器地址栏伸缩、系统返回键、相机权限、
> 微信内置浏览器、弱网。上线前请按这份清单在**真手机**上过一遍。
>
> 怎么打开：手机与电脑连同一 WiFi，浏览器访问 `http://<电脑IP>:5174`
> （dev server 已配 `host: 0.0.0.0`）。电脑 IP 用 `ipconfig` 看 IPv4 地址。

## 一、准备

| 项 | 说明 |
|---|---|
| 账号 | 普通农户账号一个（别用 admin，避免把管理端数据搞乱） |
| 机型 | 至少一台 **iPhone（刘海屏）** + 一台 **安卓**（越小屏越好，如 360×640） |
| 浏览器 | iOS Safari + 微信内置浏览器；安卓 Chrome + 微信内置浏览器 |
| 网络 | 先正常 WiFi 走一遍，再**关掉 WiFi 只留流量/开飞行模式**走一遍 |

## 二、必测项（每条都写清"怎么做 / 期望什么"）

### 1. 首屏与地址栏（iOS Safari 最容易出问题）

* **怎么做**：Safari 打开后**上下滑动**页面。
* **期望**：内容不被底部地址栏遮住；滑动时不会出现"半屏空白"或内容跳动。
* **备注**：iOS 的 `100vh` 不等于可视高度（地址栏会伸缩）。若发现底部按钮被遮，
  记录**机型 + iOS 版本 + 哪一页**。

### 2. 安全区（刘海屏 / 全面屏）

* **怎么做**：看识别页顶栏、记录页底部标签栏、结果页底部按钮。
* **期望**：顶栏不被刘海压住；底部内容不被"横条"压住。
* **备注**：无 TabBar 的页面（结果/登录）已垫 `env(safe-area-inset-bottom)`。

### 3. 拍照识别（**最关键的一条**）

* **怎么做**：识别页 →「拍照识别」→ 允许相机权限 → 拍一张叶片 → 等结果。
* **期望**：能唤起相机；拍完能看到预览；点「开始识别」后**进度条会动**；
  几秒内跳到结果页并显示**中文病害名 + 置信度 + 症状/防治建议**。
* **记录**：从点"开始识别"到出结果**几秒**（弱网下多久）。

### 4. 从相册选图

* **怎么做**：识别页 →「从相册选」→ 选一张相册里的叶片照片 → 识别。
* **期望**：同上；且**大图（>5MB）不会报"图片太大"**（前端会自动压缩，见第 165 批）。

### 5. 切 tab 不丢照片（第 91 批的承诺）

* **怎么做**：识别页选好照片（**先别点识别**）→ 点底部「记录」→ 再点回「识别」。
* **期望**：**照片还在**，可以直接点"开始识别"，不用重拍。
* **备注**：这条已由 `verify-main-flow.mjs` 自动验过（点底部导航切页），真机再确认一次
  —— 田里戴手套重拍一张的代价很高。

### 6. 记录页

* **怎么做**：进「记录」→ 下拉刷新 → 左滑某条记录 → 删除。
* **期望**：下拉能刷新；左滑出现删除；删完列表少一条且**刷新后确实没了**。

### 7. 离线与补传（农户田里常没信号）

* **怎么做**：识别页选好照片 → **开飞行模式** → 点"开始识别" → 看提示 →
  关掉飞行模式，等一会儿。
* **期望**：提示已存到本地、稍后自动补传；恢复网络后**自动补传成功**并在记录页出现。
* **备注**：顶部会出现离线指示条（`OfflineIndicator`）。

### 7b. 一键求助（复制求助文案，第 176 批）

* **怎么做**：识别出结果后往下滑到「遇到拿不准的，问问大家」→ 点「复制求助内容」→
  打开微信，粘到群里或粘给自己看。
* **期望**：出现"已复制"提示；微信里能粘出**完整一段话**：
  病名、把握多大、主要症状、防治建议、照片链接、一句提问。
* **⚠️ 两个真机上才会遇到的点**：
  1. **HTTP 局域网下浏览器不给用剪贴板 API**（`navigator.clipboard` 是空的）——
     代码已做两层回退，若**两种都失败**会弹窗把文案显示出来，**长按选中复制**即可
     （宁可多一步，也不能"点了没反应"）；
  2. 照片链接是**局域网地址**（`http://192.168.x.x:...`）—— **只有连同一个 WiFi 的人打得开**；
     发给外地的亲友他们点不开 ✗。上线部署到公网域名后这条自然解决。
     如果这条链接会误导人，就只复制文字部分（告诉我即可）。

### 8. 安卓物理返回键 / iOS 侧滑返回

* **怎么做**：在结果页、记录页、登录页分别按返回。
* **期望**：回到上一页而不是直接退出；从分享链接（直接进结果页）返回时**不应该白屏**
  （顶栏返回按钮在无历史时会回识别页）。

### 9. 微信内置浏览器

* **怎么做**：把 `http://<电脑IP>:5174` 发到微信里打开。
* **期望**：页面能正常用；拍照/相册能唤起（微信里走的是它自己的选择器）。
* **备注**：微信里**不能**用 `navigator.mediaDevices` 的部分能力，页面已做回退（系统相机）。

### 10. 小屏与横屏

* **怎么做**：安卓小屏机（360×640）走一遍；再**横过来**看识别页与结果页。
* **期望**：小屏上按钮不重叠、文字不溢出；横屏下内容可滚动、按钮可点。
* **备注**：横屏未做专门适配（本项目按竖屏设计），只要"能用"即可，记录明显问题。

## 四、这台机器上已知的、**不用报**的现象

| 现象 | 原因 |
|---|---|
| 电脑上按 F12 切手机尺寸时，截图上沿有一条浏览器条 | 那是模拟器自己的界面，不是应用内容 |
| 开发模式下首屏略慢 | Vite 按需编译；`npm run build` 后不会这样 |
| 手机首次打开会提示"不安全/继续访问" | dev server 走 HTTP，没有证书 |
| 切语言后个别 Vant 组件文案没变 | 已知：命令式 `showToast()` 走 `Locale.use()`，页面需刷新一次（见 App.vue 注释） |
| 深色模式没有跟随系统 | **当前未支持深色模式**（后续批次可做） |
