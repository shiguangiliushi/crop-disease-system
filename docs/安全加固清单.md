## §1 额度伪造（已修）

- **现象**：`curl -H 'X-Forwarded-For: 1.2.3.4' …/api/guest/session/` 等于换了一个 IP，
  而额度按 IP 计 ⇒ 一个 header 换无限免费识别。
- **修法**：`api/audit._client_ip()` 改为 `X-Real-IP` → `X-Forwarded-For` **最右** → `REMOTE_ADDR`。
- **验收**：

```bash
sudo docker compose exec -T backend python manage.py shell -c "
from api.audit import _client_ip
class R: META={'HTTP_X_FORWARDED_FOR':'6.6.6.6, 203.0.113.7','REMOTE_ADDR':'203.0.113.7'}
print('取到的 IP =', _client_ip(R()))"      # 期望 203.0.113.7（不是 6.6.6.6）
```

## §2 跨 IP 刷识别 → nginx 限速（需你执行）

> **一键做掉（推荐）**：`sudo bash deploy/harden.sh --check` 预演，去掉 `--check` 执行。
> 脚本会：备份 nginx.conf → 插入 zone 与两个精确 location → `nginx -t`（带网络与证书，
> 失败自动回滚）→ reload nginx → 修 crontab → 写 `DJANGO_GUEST_TRIAL`。
> 幂等，可重复跑。下面是它做的事的等价手工步骤。

代码层的额度是"每 IP 每天 3 次"，换 IP 就刷新。只有反代能按来源 IP 限速。

```bash
cd /home/ubuntu/app
cp deploy/nginx.conf ~/nginx.conf.before-ratelimit.$(date +%m%d)

# 把 deploy/nginx/security-snippets.conf 的 §1、§2 合并进 deploy/nginx.conf：
#   · limit_req_zone 三行 → http { } 里（和 upstream 同级）
#   · 两个 location = …  → 443 的 server { } 里
#   · limit_req zone=crop_api 一行 → 现有的 location /api/ { } 里

sudo docker run --rm --network app_default \
  -v $PWD/deploy/nginx.conf:/etc/nginx/conf.d/default.conf:ro \
  -v $PWD/deploy/certs:/etc/nginx/certs:ro \
  nginx:1.27-alpine nginx -t

sudo docker compose up -d --force-recreate nginx
```

**验收**（连发 8 次，应看到 429）：

```bash
for i in $(seq 1 8); do
  curl -s -o /dev/null -w "%{http_code} " -X POST https://www.shiguangiliushi.com/api/guest/session/
done; echo
# 期望：前几次 201，之后 429
```

## §3 识别限流（已修）

- `DetectView` 挂上 `ScopedRateThrottle`（scope=`detect`，10/min/身份）。
- 游客另有"每 IP 每天 3 次"的库内额度（`GuestTrialQuota`）。
- **注意**：DRF 限流在 LocMem 缓存下是"每进程一份"，你们已配 Redis ⇒ 生效正常。

## §4 游客账号洪泛

- 限流 `guest_session` 从 6/min 降到 **2/min**（第 441 批）。
- 仍要挂清理任务（见 §5）。想更保守可把 `DEFAULT_THROTTLE_RATES['guest_session']` 改 `1/min`。

## §5 定时任务（必须做）

```bash
cd /home/ubuntu/app
crontab -l > ~/crontab.bak.$(date +%m%d%H%M)
sudo mkdir -p /var/log/crop-disease && sudo chmod 777 /var/log/crop-disease

# ① prune_media 补 --yes（原来少了它 = 每天只打报告不删文件）
sed -i "s#manage.py prune_media >>#manage.py prune_media --yes --min-age-days 7 >>#" <(crontab -l) | crontab -

# ② 追加游客清理（05:00）
(crontab -l; echo "0 5 * * * cd /home/ubuntu/app && sudo docker compose exec -T backend python manage.py prune_guests --days 3 --yes >> /var/log/crop-disease/guests.log 2>&1") | crontab -

crontab -l | grep -E 'prune_media|prune_guests'
```

**验收**：

```bash
sudo docker compose exec -T backend python manage.py prune_guests --days 3      # dry-run，看候选数
```

## §6 试用开关（部署时）

```bash
cd /home/ubuntu/app
grep -q '^DJANGO_GUEST_TRIAL=' backend/.env || echo 'DJANGO_GUEST_TRIAL=True' >> backend/.env
grep -n '^DJANGO_GUEST' backend/.env
```

- 想先内部验证再放开：写 `False` → 重启 → 验证完改 `True` → 再重启；
- 止血：线上被刷时改成 `False` 并 `up -d --force-recreate backend` —— **已开页面的游客也会立刻失效**。

## §7 SSH 限源（云控制台，1 分钟）

腾讯云 → 轻量应用服务器 → 防火墙 → 编辑 `22/TCP` 规则 → 来源改成**你的出口 IP**
（家里/公司固定 IP；不确定就先 `curl -s ifconfig.me` 看当前出口）。
顺带确认 80/443 仍是 `0.0.0.0/0`。
