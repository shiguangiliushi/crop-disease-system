## 二、入库映射（已逐项核对代码，非推测）

### 2.1 病害 26 条 → 既有表，**零 schema 改动**

| JSON | 落点 | 说明 |
|---|---|---|
| `name` | `PestInfo.name` | 按名匹配既有 26 条 |
| `host_crop` | `PestInfo.crop_type` | 只取中文作物名部分（去学名） |
| `dimensions["症状描述"]` | `PestInfo.symptoms` | |
| `dimensions["发病规律"]` | `PestInfo.description` | **关键**：前端"发病规律"就是这个字段 |
| `dimensions["农业防治"]` | `PreventionMethod(category='AGRICULTURAL').measure` | |
| `dimensions["化学防治"]` | `PreventionMethod(category='CHEMICAL').measure` | |
| `dimensions["生态防治"]` | `PreventionMethod(category='ECOLOGICAL').measure` | |
| `dimensions["物理防治"]` | `PreventionMethod(category='PHYSICAL').measure` | |
| `dimensions["监测预警"]` | `PreventionMethod(category='MONITORING').measure` | |
| `scientific_name` | **新增字段** `PestInfo.scientific_name` | |
| `sources` | **新增字段** `PestInfo.sources = JSONField(default=list)` | 回答要能引用来源 |
| `calibration_notes` | **不入库**（留档在 [数据校准说明.md](knowledge_base/数据校准说明.md)） | 是给维护者看的修订说明 |

**为什么"发病规律→description"是对的**（易误判，已核对）：

```python
# api/serializers.py:457 —— PestInfoSerializer
def get_trigger(self, obj):
    return obj.description or '暂无发病规律信息'
```

即既有约定就是 `description` == 发病规律。语义对齐，**不要改这一层**。

**副产品收益**：`api/views.py:1531` 的全站搜索是 `Q(symptoms__icontains) | Q(description__icontains)`，
入库后**搜索立刻变准**（原来只能搜到 40 字的摘要）。

### 2.2 健康 12 条 → **必须新开一张表**

`healthy` 的 7 个维度（形态特征 / 生长条件 / 农业·化学·生态·物理管理 / 健康监测）在现有 schema 里**没有家**：
`PestInfo` 是病害表、`CropVariety` 是品种表（`name`+`description`），语义都不对。

```python
# api/models.py 追加（方案 A）
class CropHealthProfile(models.Model):
    """作物健康管理档案（校准版知识库 healthy 记录）。

    与 PestInfo 的关系：既有库里有 12 条 `*_healthy` 词条（如"健康番茄"），
    那是**识别用**的；本表是**栽培管理用**的档案。用 `pest` 外键把两者接起来，
    不合并——识别链路的词条匹配不应被栽培内容污染。
    """
    pest         = OneToOneField('PestInfo', null=True, blank=True,
                                 on_delete=SET_NULL, related_name='health_profile')
    crop_type    = CharField(max_length=100, db_index=True)          # 番茄
    name         = CharField(max_length=255)                         # 健康番茄
    scientific_name = TextField(blank=True, default='')
    morphology   = TextField('健康形态特征')          # + morphology_en
    growing_conditions = TextField('健康生长条件')     # + growing_conditions_en
    care_agricultural  = TextField('农业健康管理', blank=True, default='')
    care_chemical      = TextField('化学保护', blank=True, default='')
    care_ecological    = TextField('生态健康管理', blank=True, default='')
    care_physical      = TextField('物理保护', blank=True, default='')
    care_monitoring    = TextField('健康监测', blank=True, default='')
    sources      = JSONField(default=list, blank=True)
    updated_at   = DateTimeField(auto_now=True)
```

> 方案 B（折进 `CropVariety` 加列）不推荐：迁移量一样，却把"品种"与"健康栽培"两个概念混表。

### 2.3 唯一的名字不一致（必须人工映射）

| JSON `name` | 库中 `PestInfo.name` | `english_identifier` |
|---|---|---|
| 番茄斑靶病 | **番茄靶斑病** | `tomato_target_spot` |

按 `english_identifier` 或显式别名表匹配，**不要按名字直接查**，否则这条会漏。

另外 `南瓜白粉病`（`pumpkin_powdery_mildew`）不在模型 39 类里，但它在 `PestInfo` 中（id=26），正常入库即可。

## 三、⚠️ 初稿 PDF 的内容**禁止入库**

`数据校准说明.md` 第四节列出 10 处实质性纠错，其中 5 处是**会答错药、答错病原**的错误：

| 记录 | 初稿（PDF） | 校准版（JSON） |
|---|---|---|
| 马铃薯晚疫病 | 推荐**甲霜灵** | 2024 全国抗药性监测：甲霜灵高抗菌株 >80%，**主产区停用**，改烯酰吗啉/氟菌·霜霉威/氰霜唑/氟啶胺/氟噻唑吡乙酮轮换 |
| 桃细菌性斑点病 | 病斑 **2 cm** | 叶斑约 **2 mm**、果斑约 **1 mm**；且农用链霉素国内已限用，改中生菌素/春雷霉素 |
| 番茄细菌性斑点病 | 病原写作**黄单胞杆菌** | 实为 *Pseudomonas syringae* pv. *tomato*（bacterial speck），偏好**冷凉 16–24 ℃**（初稿写 25–30 ℃ 高温高湿，方向相反） |
| 葡萄叶枯病 | 与 **Esca 黑麻疹**混为一谈 | 实为 *Pseudocercospora vitis* 叶部斑点病，不侵染果实 |
| 苹果黑星病 | "富士、嘎啦较**抗**病" | 富士、嘎啦系实际**感**病 |

结论：**只从 JSON 入库**。初稿 PDF（`作物病害防治知识库.pdf`、`作物健康管理知识库.pdf`）仅作对照留档；
我已删掉上一轮从 PDF 抽出的 `.records.tsv` 等中间产物，避免被误用。

| 阶段 | 动作 | 验收 |
|---|---|---|
| **K0** | 数据归档到 [docs/knowledge_base/](knowledge_base/) | ✅ 已完成（json / md / 校准说明三件，SHA256 已核对） |
| **K1** | `api/management/commands/load_kb.py`：`--dry-run` 只读比对 | 打印"匹配 26 条（含 1 条走别名）· 将更新 26×2 知识字段 · 将写 130 条防治 · 12 条健康"，**一字不写库** |
| **K2** | 迁移：`PestInfo.scientific_name` / `PestInfo.sources` / `CropHealthProfile` | `manage.py check` 通过 |

## 五、必须写进助手提示词的硬约束（来自校准说明）

1. **农药时效性**：化学防治按 FRAC 分组轮换；`metadata.calibration_date = 2026-10-14`，**每 1–2 年复核**。
2. **禁用清单**：甲霜灵（马铃薯晚疫病，高抗）、农用链霉素（桃细菌性斑点病，国内限用）——语料里写的是"停用/替代"，提示词必须原样传达，**不许模型"好心"补回**。
3. **安全间隔期与每季最多使用次数**必须原样引用，不得省略。
4. **免责**：`数据校准说明.md` 第六节明确"本知识库不构成农药使用推荐，以当地植保站当期防治方案为准"——助手回答涉及用药时必须带这句。
5. **只依据检索到的语料作答**，无来源则答"词条未收录，建议咨询当地植保站"。

## 六、检索粒度（校准说明第六节的建议）

- 首选 **一条记录 = 一个文档块**（38 块），38 块规模下关键词检索足够，**先不要上向量库**；
- 若答案太长（最长 353 字的化学防治段），按 **7 个维度**再切一层作为二级块，检索命中后按维度拼装；
- 每条块携带 `sources`，回答时按序号引用 `[1]`。

## 七、尚缺清单

| # | 缺口 | 影响 |
|---|---|---|
| 1 | `scientific_name` / `sources` 字段不存在 | 学名与来源无处安放，只能塞进 `description`（会污染前端展示） |
| 2 | 12 条健康记录无表可入 | 需 K2 迁移 |
| 3 | 无导入命令 | 手工写脚本易重复导入（防治措施会翻倍） |
| 4 | 全库无英文字段内容 | 英文界面回退中文（可调既有翻译服务补） |
| 5 | `PreventionMethod` 无唯一约束 | 幂等必须靠"先删后写"实现 |
| 6 | 语料覆盖面：26/39 类 | 13 个模型类目仍无知识库（含若干 `healthy` 之外的类） |

## 八、明确不做

- **不**用初稿 PDF 的内容（见第三节）；
- **不**把 `calibration_notes` 给用户看（是维护者文档）；
- **不**改 `PestInfo.description` 的语义（它已经是"发病规律"）；
- **不**在 38 条规模下引入向量检索 / 重排模型。
