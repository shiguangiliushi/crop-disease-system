# 角色与权限矩阵

> 本文件由 `python manage.py role_matrix --write-docs` **生成**，请勿手改。
> 唯一来源：`backend/api/role_matrix.py`（表）+ `backend/api/capabilities.py`（判定）。
> 一致性由 `api.tests.RoleMatrixTests` 保证：表与代码不一致时测试会红。

## 一、三个角色

| 角色 | 说明 |
|---|---|
| `ADMIN` | 全权管理员：三个能力全给，五个内容模块全给（不查授权表） |
| `EDITOR` | 信息编辑员：只有 CONTENT，且只限被勾选的模块；碰不到账号与他人数据，也不能对全体发声 |
| `USER` | 普通农户：只能用自己的识别/记录/论坛等农户端功能，进不了管理后台 |

## 二、信息编辑员：五个内容模块各自能做什么

授权方式：在控制台「用户管理」里开通编辑员并勾选模块（写进 `EditorModuleGrant` 表）。
**全权管理员五个模块全有**（不查授权表）；编辑员只有被勾的那些；其余账号一个都没有。

| 模块 | 名称 | 能进的管理页 |
|---|---|---|
| `review` | 内容审核 | /admin/content |
| `forum` | 论坛交流 | /admin/content |
| `news` | 新闻管理 | /admin/news |
| `pests` | 病害百科 | /admin/pests |
| `feedback` | 意见反馈 | /admin/feedback |

⚠️ 两个模块在"评论与帖子"上是**或**的关系：勾了「内容审核」**或**「论坛交流」都能管（`review` 是宽口径，老账号不会因为拆分掉权限）。

⚠️ 第 183 批：原「内容审核 / 论坛管理 / 评论管理」三页合并成**一个页面**`/admin/content`「内容管理」，页内三个页签 ——

* **帖子**、**评论**两个页签：`review` **或** `forum` 任一即可（上表的两个模块都指向它）；
* **举报**页签：第 189 批起同样是 `review` **或** `forum`，但**只放开一半** ——编辑员能看别人的举报、能处置（改状态 + 备注），**看不到举报人是谁**（回包匿名化：`reporter.username` 为 null、`target_user_id` 不下发），也**不能**「同时隐藏内容」（不可逆动作只给全权管理员，传了不生效且会明确告知）；
* 旧地址 `/admin/review`、`/admin/forum`、`/admin/comments` 保留为重定向，分别落到对应页签（书签与外链不失效）。

## 三、非内容能力与"仅全权管理员"

| 能力/标记 | 能进的管理页 | 说明 |
|---|---|---|
| `USER_ADMIN` | /admin/users | 用户账号与他人数据（含跨用户识别记录） |
| `BROADCAST` | /admin/health | 对全体用户发声与系统开关（公告/预警/敏感词/版块） |
| （任何能进后台的人） | /admin/dashboard | 只读聚合，没有他人明细 |
| `FULL_ADMIN` | /admin/health | 会暴露部署细节或"谁对谁做了什么" |

**不可逆动作一律只给全权管理员**（不塞进任何模块）：
删除意见反馈、彻底删除评论 —— 见 `capabilities.py` 的说明。

## 四、接口矩阵

★ = 仅全权管理员。判定语义：`allow` 里**任一命中**即可（与代码里的 `or` 一致）。

| | 方法 | 接口 | 允许 | 说明 |
|---|---|---|---|---|
|  | `GET` | `/api/admin/comments/` | review、forum | 控制台评论列表（跨帖子） |
|  | `POST` | `/api/admin/comments/bulk-delete/` | review、forum | 批量软删除评论 |
|  | `POST` | `/api/admin/comments/1/soft-delete/` | review、forum | 软删除单条评论（内容置为已删除） |
| ★ | `DELETE` | `/api/admin/comments/1/` | FULL_ADMIN | 彻底删除评论（不可逆） |
|  | `GET` | `/api/reports/` | review、forum | 举报列表与待处理计数（举报人身份仅全权管理员可见） |
|  | `POST` | `/api/reports/1/handle/` | review、forum | 处置举报（改状态 + 备注；同时隐藏内容仅全权管理员） |
|  | `POST` | `/api/news/` | news | 新建新闻 |
|  | `PUT` | `/api/news/1/` | news | 修改新闻 |
|  | `DELETE` | `/api/news/1/` | news | 删除新闻 |
|  | `POST` | `/api/pests/` | pests | 新建病害词条 |
|  | `PUT` | `/api/pests/1/` | pests | 修改词条 |
|  | `DELETE` | `/api/pests/1/` | pests | 删除词条 |
|  | `POST` | `/api/pests/import/` | pests | 批量导入词条 |
|  | `POST` | `/api/calendar/tasks/` | pests | 农事任务（与百科同属"给农户看的农业资料"） |
|  | `POST` | `/api/feedback/1/reply/` | feedback | 回复反馈 |
|  | `POST` | `/api/feedback/bulk-status/` | feedback | 批量流转状态 |
| ★ | `POST` | `/api/feedback/bulk-delete/` | FULL_ADMIN | 批量删除反馈（不可逆） |
|  | `GET` | `/api/admin/users/` | USER_ADMIN | 用户列表 |
|  | `POST` | `/api/admin/users/1/reset-link/` | USER_ADMIN | 签发密码重置链接 |
|  | `DELETE` | `/api/admin/users/1/` | USER_ADMIN | 删除账号 |
|  | `GET` | `/api/admin/detections/` | USER_ADMIN | 识别记录（跨用户，含用户身份） |
|  | `GET` | `/api/sensitive-words/` | BROADCAST | 敏感词列表 |
|  | `POST` | `/api/sensitive-words/` | BROADCAST | 新增敏感词 |
|  | `POST` | `/api/announcements/` | BROADCAST | 发布系统公告 |
|  | `POST` | `/api/forums/boards/` | BROADCAST | 新建论坛版块 |
| ★ | `GET` | `/api/admin/health/` | FULL_ADMIN | 系统健康（暴露服务器路径与部署细节） |
| ★ | `GET` | `/api/admin/audit-logs/` | FULL_ADMIN | 操作日志（谁对谁做了什么） |

## 五、自查

```bash
python manage.py role_matrix                 # 打印完整矩阵
python manage.py role_matrix <用户名>        # 这个账号到底能干什么
python manage.py role_matrix --write-docs    # 重新生成本文件
```

最常用来回答的问题是"我明明给他勾了新闻管理，他怎么还是看不到" —— 跑一次带用户名的自查，能直接看到他此刻的能力、模块与逐条接口判定。
